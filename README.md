# Meeting Intelligence System

A robust, local-first meeting intelligence extraction pipeline that automatically transcribes audio, performs speaker diarization, generates contextual summaries via BART, and leverages local LLMs (Qwen 2.5: 3B) via Ollama to extract strictly mapped Action Items and Key Decisions.

## Features
- **Member 1: Audio Processing & Diarization**: Uses `faster-whisper` for transcription and `pyannote/speaker-diarization-3.1` to accurately map segments to speakers.
- **Member 2: Semantic Segmentation & Summarization**: Groups transcript segments into contextual topics and uses a BART summarization model to distill key information.
- **Member 3: Pure LLM Semantic Extraction**: Uses strict, few-shot prompting via Ollama (`qwen2.5:3b`) to precisely extract tasks and decisions, outputting strictly structured JSON validated by Pydantic.
- **Member 4: (In Progress)**: Aggregates JSON output into a consumable UI/Report.

## System Requirements

- **Python 3.12+**
- **FFmpeg**: Required for audio processing. Must be installed and accessible in your system's `PATH`.
- **Ollama**: Required for local LLM inference. Must be installed and running as a service.

## Setup Instructions

### 1. Clone & Environment Setup
Clone the repository and create a Python virtual environment:

```powershell
git clone https://github.com/Kaushal1122/meeting-intelligent-system.git
cd meeting-intelligent-system
python -m venv venv
venv\Scripts\Activate.ps1
```

### 2. Install Dependencies
Install all required packages from the frozen requirements:

```powershell
pip install -r requirements.txt
```

### 3. Configure Hugging Face
The pipeline uses `pyannote/speaker-diarization-3.1` which requires a Hugging Face token.
1. Create a `.env` file in the root directory.
2. Add your token:
```env
HF_TOKEN=your_token_here
```
*(Do NOT commit your `.env` file to version control).*

### 4. Setup Ollama Model
Member 3 relies on the Qwen 2.5 (3B) model for fast, local intelligence extraction.
Ensure Ollama is running, then pull the required model:

```powershell
ollama pull qwen2.5:3b
```

## Running the Pipeline

You can run the entire pipeline end-to-end, providing an audio file. The pipeline will automatically handle transcription, topic segmentation, summarization, and LLM intelligence extraction.

```powershell
python backend\pipeline.py --audio "data\ami\amicorpus\ES2002c\audio\ES2002c.Mix-Headset.wav"
```

If you want to skip audio transcription and run from an existing transcript JSON:

```powershell
python backend\pipeline.py --transcript "data\processed\ES2002c.Mix-Headset_speaker_transcript.json"
```

### Outputs
All outputs are generated dynamically in the `data/processed/` directory.
- `<meeting_id>_speaker_transcript.json` (Member 1 Output)
- `<meeting_id>_member2_results.json` (Member 2 Output)
- `<meeting_id>_member3_results.json` (Member 3 Output)

## Member 4: Handoff & UI Integration Guide

Member 4 is responsible for consuming the intelligence generated by Member 3 and presenting it in a UI or automated report.

**Data Contract:**
Member 4 should exclusively ingest the `<meeting_id>_member3_results.json` file from the `data/processed/` directory. This file contains the fully structured, Pydantic-validated list of `action_items` and `key_decisions`, including `topic_reference` integers that map back to the full transcript topics.

**Environment Setup for Member 4:**
1. **Virtual Environment**: Use the same `venv` created in Step 1.
2. **UI Framework**: If building a UI, you may install Streamlit (`pip install streamlit`) or FastAPI depending on the architecture.
3. **Evaluation Layer**: To evaluate the extraction quality, cross-reference the `needs_human_review` boolean flags in the Member 3 output JSON to build a "Human-in-the-Loop" approval dashboard.
